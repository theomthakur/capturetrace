SYSTEM DESIGNREFERENCE ARCHITECTURE

One event. Clear boundaries. No silent failure.

CaptureTrace separates field capture, durable delivery, boundary validation, and workflow state. The browser demo simulates these guarantees. This page explains how the design maps to a production system without claiming to represent another company's internal architecture.

02 / EXACT EVENT JOURNEY

What happens during one complete run

This is the common end-to-end sequence behind every prepared scenario.

  1. 01

    Read

    The synthetic CT-07 tool produces a measurement and device sequence.

  2. 02

    Envelope

    The app creates `measurement.v3` with a stable event ID and explicit job and field context.

  3. 03

    Persist

    The app records the event locally before attempting network delivery.

  4. 04

    Transport

    If connected, the app sends immediately. If offline, the outbox retains the event.

  5. 05

    Identify

    The receiver checks whether this event ID has already been accepted.

  6. 06

    Validate

    The receiver checks contract version, units, field context, device metadata, and sequence.

  7. 07

    Decide

    The event becomes accepted, duplicate, queued, or review. Every non-accepted state has a reason.

  8. 08

    Reflect

    The field form, integrity trace, metrics, and export report reflect the same outcome.

03 / STATE MODEL

Four visible outcomes

Transport state and trust state are not treated as the same thing.

ACCEPTED

Trusted and applied

Identity and contract checks pass. The measurement fills the intended form field.

QUEUED

Safe but not delivered

The event is retained locally. It is not shown as trusted until replay succeeds.

DUPLICATE

Previously accepted

The same ID arrives again after a retry. The receiver suppresses the second write.

REVIEW

Delivered but uncertain

The event reached the receiver but failed a contract or context rule. A person must decide.

05 / CORE DECISIONS

Why the system behaves this way

  1. 01
    Store before send

    Delivery becomes retryable work rather than a one-time hope.

  2. 02
    Retry with the same identity

    A repeated delivery cannot create another measurement.

  3. 03
    Validate at the boundary

    Only explicit, compatible context reaches the workflow.

  4. 04
    Expose uncertainty

    The system holds unclear input instead of silently guessing.
