    02 ONE PIPELINE, FIVE TESTS

    Every scenario starts at capture and ends with a visible decision.

    The scenarios are not five steps performed in order. They are five independent runs through the same end-to-end flow. Each run changes one condition so you can see how the system responds.

    Read the complete step-by-step guide →
    1. 01
      CAPTURETool creates a measurement event

      The reading receives an ID, device, timestamp, field, units, and contract version.

    2. 02
      PERSISTApp stores it locally first

      The event remains recoverable even when delivery cannot happen immediately.

    3. 03
      DELIVERTransport sends or retries it

      Reconnects and retries reuse the same event identity.

    4. 04
      VALIDATEReceiver checks the full contract

      Identity, schema, units, context, and sequence must be acceptable.

    5. 05
      DECIDEWorkflow exposes the outcome

      The event is accepted, queued, suppressed, or held with a reason.

    What changes between runs? Clean capture: nothing fails Offline: delivery waits Lost acknowledgment: delivery repeats Wrong units: validation fails Old contract: schema validation fails
    03

    Trust travels with the event.

    The interface can change. The invariant cannot: every accepted value retains enough identity and context to explain where it came from and why it was trusted.

    01Stable identity

    Retries reuse one event ID, making duplicate delivery harmless.

    02Explicit context

    Job, field, units, device, and capture time travel with the value.

    03Visible state

    Queued and held events are surfaced instead of appearing successful.

    04Safe ambiguity

    Unexpected context pauses for confirmation; it is never silently guessed.

    SYSTEM NOTES

    What this prototype proves

    01

    Local-first capture

    A capture is assigned an identity and retained before network delivery is attempted.

    02

    Idempotent replay

    The receiver uses the stable event ID to make retry and reconnection safe.

    03

    Contract validation

    Units, field context, schema version, and device metadata are validated at the boundary.

    04

    Human-visible failure

    Anything uncertain enters a review state with a reason instead of disappearing or being guessed.

    Scope boundary

    This is a browser-only simulation. It is not a BLE implementation, production architecture recommendation, or representation of another company's internal system.
